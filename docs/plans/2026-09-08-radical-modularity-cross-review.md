## Defects in the proposed corrections

**Amended — R6's removal of the invalidation bound (Evidence without invalidation explosion; Agentic scalability verification).** R6 says "report invalidation fan-out instead of imposing a cap that suppresses necessary work." The diagnosis is right — a cap that suppresses required consumer verification would falsify the ledger — but the original's `ordinary invalidation gain <= 3 reviews per changed file` was a benchmark _metric_, not a suppression mechanism, and deleting it entirely discards the signal that bounded invalidation, a core design goal, has failed. Concrete revision: keep the figure as a reported diagnostic with a predeclared trigger threshold that forces a design review when exceeded, never a gate that drops verification work. R6's substantive split — deterministic consumer/conformance checks fan out cheaply on implementation changes; LLM re-review fans out only on classified behavioral change — is correct and stays.

**Amended — R10's enforcement depth versus A3's stated scope (Temporary module ownership).** The correction is sound and necessary (the original's only enforcement was "the agent refuses a write outside the packet"), but heartbeat expiry, fencing generations and stale-writer fencing are distributed-systems machinery, while A3 confines the system to one host and one Git common directory where atomic claim acquisition is trivial. Concrete revision: designate the mandatory diff-versus-packet boundary gate at admission plus atomic, ordered, all-or-nothing claim acquisition as the required core; implement generation/fencing tokens in the same change (they are cheap and cover crashed-and-resumed sessions, which will happen), but state explicitly that multi-clone/multi-host coordination is out of scope until A3 is revised. This answers the "excessive governance" criterion: the heavy parts are justified, but the document should name the minimal enforced core so implementation doesn't gold-plate.
